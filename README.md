# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса, объединяющий клиентский путь и внутреннюю обработку заявки в единый управляемый процесс.

## 🎯 Назначение решения

Решение демонстрирует **сквозной сценарий** кредитования:
1. Возникновение потребности в финансировании
2. Выбор продукта и подача заявки
3. Обработка заявки банком (проверка, обогащение, скоринг)
4. Принятие решения (одобрение / отказ / встречное предложение)
5. **Принятие условий клиентом**
6. **Подписание договора** (упрощённое)
7. **Выдача кредита** (моделирование)

## 🔄 Машина состояний заявки

```
draft → submitted → data_validation → data_enrichment → scoring → review
                                                                        ↓
                                                        ┌───────────────┼───────────────┐
                                                        ↓               ↓               ↓
                                                    approved    approved_with_changes  rejected
                                                        ↓               ↓
                                                        └───────┬───────┘
                                                                ↓
                                                      documents_pending
                                                                ↓
                                                            completed
```

**12 состояний** покрывают полный жизненный цикл заявки от создания до выдачи.

## 📊 Скоринговая модель

Балльная модель (0-100) на основе **6 факторов**:

| Фактор | Описание | Влияние |
|--------|----------|---------|
| Возраст бизнеса | Стабильность компании | -6 ... +8 |
| Рентабельность | Финансовая устойчивость | -8 ... +8 |
| Долговая нагрузка | Отношение платежей к выручке | -8 ... +7 |
| Кредитная история | Платёжная дисциплина | -8 ... +8 |
| Сумма/Выручка | Адекватность запроса | -7 ... +5 |
| Масштаб бизнеса | Размер выручки | -4 ... +5 |

**Уровни риска:**
- 🟢 Низкий (≥75) → Одобрение
- 🟡 Средний (55-74) → Одобрение с изменениями
- 🟠 Высокий (35-54) → Запрос доп. информации
- 🔴 Очень высокий (<35) → Отказ

**4 типа решений:**
1. ✅ Одобрение на запрошенных условиях
2. ⚠️ Одобрение с изменёнными условиями (сумма, ставка)
3. 📋 Запрос дополнительной информации
4. ❌ Отказ с объяснением

## 📋 Пошаговый сценарий проверки (End-to-End)

### Сценарий 1: Полное одобрение с выдачей

1. **Авторизация**: выберите «ООО "СтройМастер"» (сильный заёмщик)
2. **Каталог**: выберите «Кредит на развитие бизнеса»
3. **Заявка**: установите сумму 10 000 000 ₽, срок 36 месяцев
4. **Цель**: «Закупка строительной техники»
5. **Отправка**: нажмите «Отправить заявку»
6. **Наблюдение**: автоматическая обработка (проверка → обогащение → скоринг → решение)
7. **Результат**: заявка одобрена
8. **Принятие**: нажмите «Принять предложение и оформить»
9. **Подписание**: введите SMS-код `482913`
10. **Выдача**: нажмите «Выпустить средства на счёт»
11. **Финал**: кредит выдан, отображается итоговая информация

### Сценарий 2: Отказ (высокий риск)

1. **Авторизация**: выберите «ООО "ФудДеливери"» (убыточная компания)
2. **Заявка**: «Пополнение оборотных средств», 5 000 000 ₽, 24 мес.
3. **Результат**: отказ из-за убыточности и просрочек в истории
4. **Банковская панель**: изучите скоринг и объяснение решения

### Сценарий 3: Одобрение с изменениями

1. **Авторизация**: выберите «ИП Козлова А.М.» (микробизнес)
2. **Заявка**: «Кредит на развитие», 8 000 000 ₽, 24 мес.
3. **Результат**: одобрено с уменьшенной суммой (из-за высокой долговой нагрузки)
4. **Принятие**: клиент может принять изменённые условия

### Сценарий 4: Банковская обработка

1. **Режим «Банк»**: изучите Kanban-доску с заявками
2. **Обработка**: переведите заявку по этапам вручную
3. **Скоринг**: запустите скоринг для заявки в статусе «Рассмотрение»
4. **Детали**: изучите внешние данные (моки ЕГРЮЛ, БКИ, ФНС)

## 🔐 Авторизация

**Реализованный подход**: выбор компании из списка действующих клиентов банка.

**Обоснование**:
- Регистрация новых юрлиц не требуется (по условию кейса)
- Рассматриваются только действующие клиенты
- Упрощение допустимо для прототипа
- В production: интеграция с ЕСИА или корпоративной IAM

## 📝 Допущения

1. **Внешние сервисы** (ЕГРЮЛ, БКИ, ФНС) смоделированы локальными моками
2. **Скоринговая логика** упрощена до балльной модели (без ML)
3. **Подписание договора** моделируется SMS-кодом (без реальной ЭП)
4. **Выдача средств** симулируется без реальных проводок
5. **Данные хранятся в памяти** (без персистентного хранилища)
6. **Авторизация** упрощена до выбора компании (без реальной аутентификации)

Все допущения **явно обозначены** и **не нарушают работоспособность** основного процесса.
